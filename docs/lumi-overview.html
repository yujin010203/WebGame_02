01 · 기획

몽글몽글한 네온 아케이드, 힐링과 몽환 사이

HTML5 Canvas + Vanilla JavaScript로 만드는 탑다운 2D 감성 미니게임. 모바일 세로 비율(9:16 근사) 우선.

스토리. 모두가 잠든 밤, 작은 아기 유령 루미는 아침이 오기 전까지 밤하늘에서 떨어진 조각난 별빛을 모아 자신만의 작은 우주를 채웁니다. 딥 블루 밤하늘(#0F172A)에 떠다니는 먼지 입자, 이동 시 은은한 꼬리 잔상 — 힐링되면서도 몽환적인 분위기가 목표였습니다.

확정된 결정 사항

점수 공식

별 ×100 + 피버 파괴 ×200 + 생존 초당 +10 (게임오버 시 합산)

온라인 랭킹

Firebase Firestore. 코드는 firebaseConfig만 채우면 동작하도록 준비, 미설정 시 랭킹만 비활성화.

사운드

assets/audio/ 훅만 제공. mp3를 넣으면 재생, 없으면 무음(no-op).

그래픽

외부 이미지 없이 전부 Canvas 절차적 드로잉. Retina는 devicePixelRatio로 대응.

02 · 아키텍처

엔티티 배열 + 씬 상태머신

이 규모에 ECS나 God-object는 과설계·유지보수 문제로 배제하고, 단순한 두 축으로 구성했습니다.

  • 엔티티 배열. 별 · 장애물 · 파티클을 배열에 담고 매 프레임 update(dt) / draw(ctx)로 순회.
  • 씬 상태머신. START → INTRO → PLAYING → GAMEOVER 상태값으로 화면 전환을 제어.
  • 게임 루프. requestAnimationFrame + deltaTime 보정으로 기기별 프레임 편차 흡수.
  • 고정 내부 해상도. 450×800으로 그린 뒤 CSS 레터박스로 스케일링.
  • 입력 통합. pointermove 하나로 마우스·터치를 통합, 목표점을 lerp 감속 추적.
  • UI 분리. 게임 화면은 Canvas, 시작/게임오버 오버레이(닉네임·Top10)는 DOM으로 처리.
  • Graceful degradation. Firebase·오디오 파일이 없어도 게임은 끊김 없이 동작 — 설계의 핵심 견고성 원칙.

03 · 메커니즘

밸런스는 전부 config.js 한 곳에

수치를 한 파일에 모아 튜닝을 쉽게 했습니다. 아래는 현재 적용값입니다.

요소효과수치
별빛모으면 회복 + 점수 + 피버 게이지HP +5 · +100점
붉은 빛(레이저)경고선 후 발사, 닿으면 즉시 게임오버즉사
먼지(유도 오브)유령을 5초간 추적HP −30
빗방울(소나기)위에서 3~5개가 고르게 낙하HP −20
방어막피격 1회 무효(레이저 포함)희귀 6%
파동화면 내 장애물 일괄 제거희귀 4%
피버(슈퍼노바)별 10개 → 무적 + 파괴당 +2005초 무적
난이도스폰 잦아짐 + 속도 최대 2.8배180초에 Lv1→Lv10

HP ↔ 유령 비주얼 연동

HP가 줄면 유령 크기가 소폭 작아지고(최저 50%), 후광(shadowBlur)과 투명도가 감소하며, HP 20% 이하에서는 위험 깜빡임 연출이 들어갑니다. 상태를 숫자가 아니라 유령의 모습으로 읽게 하는 것이 핵심.

04 · 흐름 & 데이터

씬 흐름과 랭킹 스키마

START타이틀 · 닉네임 · 도움말/랭킹 모달
→

→

게임오버 시 점수 계산 → Firebase 제출 → Top10 조회 → 오버레이 표시 순으로 진행합니다. 랭킹은 닉네임당 최고점만 보장해야 했습니다.

Firestore 설계

  • 컬렉션 scores, 문서 ID = 정규화된 닉네임 → 닉네임당 1개 문서로 최고점만 유지.
  • 필드 { nickname, score, stars, survivedSec, createdAt }.
  • 제출은 트랜잭션으로 기존 score < 신규일 때만 덮어쓰기, 조회는 orderBy(score, desc) limit(10).
  • apiKey는 비밀값이 아니며 접근 제어는 Firestore 보안 규칙으로 처리.

06 · 트러블슈팅

실제로 부딪힌 문제들

증상 → 원인 → 해결 순으로 정리했습니다. 대부분 상태머신 전환과 비동기 경계에서 나왔습니다.

CASE 01

게임오버 후에도 화면 흔들림이 계속 남음

증상
HP가 0이 됐는데 마지막 피격의 화면 흔들림이 게임오버 화면까지 이어짐.
원인
update()가 scene !== 'PLAYING'에서 조기 return → 그 뒤의 shake.update(dt)가 호출되지 않아 흔들림 값이 감쇠되지 못함.
해결
onGameOver() 진입 시 shake.t = 0; shake.intensity = 0으로 즉시 정지.
53da2b4
CASE 02

‘시작화면으로’ 눌렀는데 뒤에 직전 게임 잔상

증상
홈으로 돌아가면 시작 화면 뒤 배경에 방금 하던 게임의 엔티티가 남아 비침.
원인
onHome이 씬만 START로 바꾸고 게임 상태·엔티티 배열을 초기화하지 않음.
해결
onHome에서 resetGame()을 호출해 잔상 제거.
9142399
CASE 03

랭킹 제출이 실패하면 게임오버 흐름이 꼬임

증상
네트워크·Firebase 실패 시 랭킹이 안 뜨거나, 비동기 응답 경합으로 화면 상태가 어긋남.
원인
제출/조회 실패 처리와 비동기 경합(닉네임·셰이크·씬 전환) 가드가 부족.
해결
제출이 실패해도 순위 표시는 유지, 셰이크·닉네임·비동기 가드를 보강. “랭킹을 불러올 수 없어요” 폴백으로 게임 진행엔 영향 없음.
5792b7f
CASE 04

소나기가 한곳에 뭉침 + 그걸 잡아야 할 테스트가 무의미

증상
소나기 빗방울이 겹쳐 떨어짐. 게다가 간격 테스트가 어떤 값이든 통과해 버그를 못 잡음.
원인
스폰 x좌표가 뭉침. 테스트는 인덱스별 상수 rng를 써서 지터가 상쇄 → 항상 통과하는 껍데기 테스트였음.
해결
폭을 n등분한 셀 중앙 ± 지터로 균등 분산(rainXPositions). 테스트도 인덱스별 다른 난수를 주고 각 방울이 자기 셀 안에 있는지 검증하도록 교체.
2ebd395 · 50892e4

07 · 밸런스

수치는 한 번에 정해지지 않는다

플레이 감을 보며 올렸다가 되돌리기를 반복했습니다. config.js에 값을 모아둔 설계가 이 반복을 값싸게 만들었습니다.

  • 레이저 즉사로 전환f20bffe

    붉은 빛은 데미지가 아니라 즉시 게임오버로. 일반 장애물 15→10, 별 회복 10→5로 재조정.

  • 폰트·추적속도 원복f20bffe

    타이틀 Jua 폰트를 기본폰트로 되돌리고, 유령 추적 lerp도 0.09→0.12로 원복.

  • 난이도 상향94f611b

    먼지 20→30, 빗방울 10→20으로 데미지 강화. 소나기 개수도 5~8개로 상향 시도.

  • 빗방울 개수 원복22c778d

    데미지 상향은 유지하되, 빗방울 밀도는 원래값 3~5개로 되돌림 — 밀도는 원래 감이 더 나았음.
